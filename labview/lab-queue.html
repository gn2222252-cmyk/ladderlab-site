佇列實驗室：迴圈之間傳資料

情境：上面的迴圈（生產者）定時讀 PLC 的溫度 D0，下面的迴圈（消費者）把每一筆寫進檔案。寫檔比較慢，所以中間放一條 Queue 當緩衝：生產者 Enqueue 放進去，消費者 Dequeue 依序拿出來，先進先出（FIFO）。先按「Obtain Queue」建立佇列，再按「開始執行」。

重點：max queue size 只能在 Obtain Queue 時決定（-1 表示不設上限，只受記憶體限制），要改就得重新 Obtain。佇列滿了，Enqueue Element 會停在原地等到有空位（它的 timeout 預設 -1，一直等），所以生產者迴圈也跟著慢下來，資料不會被丟掉。Dequeue Element 在佇列空的時候會等；timeout 設 -1 就一直等，設成毫秒數則時間到就往下走，這時 timed out? 輸出 True，element 是該型別的預設值（數值就是 0），記得用 timed out? 判斷，不要把這個 0 當成真的資料存進檔案。

同一串資料 1、2、3、4、5 快速送出（每一步送一個），接收端比較慢，每拿一筆要忙好幾步。三種傳法並排跑，看接收端最後拿到什麼。

Queue：每一筆都排隊，一筆不掉、不重複，順序不變，適合「每筆都要處理」的資料（量測紀錄、要寫檔的資料、指令）。Notifier：只存最新的一筆，新的會蓋掉還沒被拿走的舊值；等待的一方只會拿到「它還沒看過的最新值」，不會重拿同一筆。適合「只要知道最新狀態」的情況，例如畫面要顯示目前溫度、或廣播一個「該停了」的訊號給好幾個迴圈。Local Variable：沒有「新資料來了」的概念，讀的一方照自己的速度讀，太慢會漏、太快會重讀同一個值，兩邊都不知道。

生產者迴圈按了 Stop 會停，可是消費者還卡在 Dequeue 等資料，怎麼通知它也停？而且生產者停下時手上還有一筆「最後的讀值」要送。選一種關法，按 ▶ 開始，等佇列堆了幾筆再按 STOP。

對的順序：生產者停下時，先把最後的資料 Enqueue，再 Enqueue 一個特殊的 Exit 訊息（例如資料型別用 cluster「命令＋數值」，命令填 Exit）。因為佇列先進先出，Exit 一定排在所有資料後面，消費者處理完前面每一筆才會看到它。兩個迴圈都結束後才 Release Queue（把佇列參考接到兩個迴圈外面，用資料流保證順序）。
另一種常見寫法是讓生產者直接 Release Queue：正在 Dequeue 等待的消費者會收到錯誤 1122，用這個錯誤停迴圈（停下後記得把 1122 清掉，不要當成真的錯誤跳視窗）。但佇列裡還沒拿走的資料就跟著佇列一起沒了，所以只有在「剩下的資料丟掉也沒關係」時才這樣做。
補充：Release Queue 有一個 remaining elements 輸出，會把還沒被拿走的元素交回來；沒接線就等於丟掉。正在 Dequeue 等待的消費者遇到 Release 會收到錯誤 1122；如果它是在 Release 之後才呼叫 Dequeue，拿到的是「參考無效」的錯誤，不是 1122。
