VISA 實驗室：位元組怎麼在線上走

序列埠一次只送一個位元。每個字元前面加一個起始位元（0），接著是資料位元（最低位先送），可能再加一個同位位元，最後是停止位元（1）。沒有資料時線路保持在 1。兩邊要先約好鮑率、資料位元、同位、停止位元，接收端才知道每個位元多長、要切幾刀。本課程的 FX3S 用 9600 7E1（9600 bps、7 個資料位元、偶同位、1 個停止位元）。

每個字元的時間 ＝ 位元數 ÷ 鮑率。7E1 和 8N1 都是 1＋7＋1＋1 ＝ 1＋8＋0＋1 ＝ 10 個位元，所以 9600 bps 一秒最多約 960 個字元，一個字元大約 1.04 ms。這裡算的是字元一個接一個、中間沒有空檔的最快情況；實際上還要加上 PLC 處理命令、轉接器的時間。
接收端看到起始位元的下降邊緣後，照自己的鮑率在每個位元的正中間取樣（波形上的圓點）。鮑率不同，取樣點就會越走越偏，切出來的是別的字元，甚至把資料位元當成起始位元；同位或資料位元數不同，就會出現同位錯誤或停止位元不是 1（框架錯誤）。這種情況兩邊都不會「自動修正」：封包收壞了，PLC 不會照你的意思回答；如果它乾脆不回，LabVIEW 這邊看到的就是 VISA Read 逾時。所以通訊不通時，第一件事是核對兩邊的四個設定。
波形畫的是邏輯準位（1 高、0 低）。RS-232 線上的實際電壓是反過來的，RS-485 則是看兩條線的電壓差，但位元的排法一樣。

VISA Write 把命令送出去以後，VISA Read 開始等。進來的位元組先放進電腦的接收緩衝區，VISA Read 從緩衝區拿。它會在下面三件事哪一件先發生就返回：① 拿滿 byte count 個位元組；② 拿到終止字元（要先開啟 Enable Termination Char，終止字元本身也會一起回傳）；③ 等到逾時，這時回傳錯誤 -1073807339。沒被拿走的位元組留在緩衝區，下一次 Read 會先拿到它們。注意：VISA Configure Serial Port 的 Enable Termination Char 預設是開的（終止字元 \n，0x0A）。FX 的回應是二進位意義的 ASCII 封包，校驗碼或資料裡剛好出現 0A 就會提前返回，所以課程把它關掉（接 F）。

本課程對 FX 的寫法：關掉終止字元，byte count 照命令算準（讀 n 個字回 4n＋4 個字元）。原因是 FX 回應的結尾是 ETX 後面還跟著 2 個校驗字元；把終止字元設成 ETX，Read 會在 ETX 就返回，校驗字元被留在緩衝區，下一次 Read 先拿到的就是這 2 個舊字元，之後每一筆都錯位。反過來，很多文字型的儀器每行用 \r\n 結尾、長度不固定，就適合開終止字元、byte count 給大一點。
逾時不一定是程式錯：PLC 沒接、COM 設定不一樣、封包格式錯讓 PLC 不回答、byte count 比對方實際回的多，最後都會變成同一個逾時錯誤。

另一種寫法：先讀 VISA 的屬性 Bytes at Port（緩衝區裡現在有幾個位元組），再把這個數字接到 VISA Read 的 byte count。這樣 Read 不會等、也不會逾時，但它只拿「這一刻已經到的」。下面假設 PLC 在命令送完 15 ms 後開始回 8 個字元（D100 = 1234 的回應），拉動 Wait 的長度看看讀到什麼。

陷阱在於：PLC 什麼時候開始回、回多快，每次不一定一樣（掃描時間、轉接器、線長都有影響）。Wait 抓太短就拿到半個封包，拿去檢查 STX、ETX、校驗一定失敗，剩下的半個還會留到下一圈，跟下一筆混在一起；抓太長則每一圈都白白多等。
所以「Bytes at Port ＋ Read」比較適合不知道對方會送多少、要自己把收到的東西接起來再找結尾的情況（例如一直監看一條線）。這時要用 Shift Register 把每次讀到的字串接起來，等湊到完整的一包（看到 ETX 再加 2 個校驗字元）才處理。像本課程這種「問一句答一句、長度算得出來」的通訊，直接把 byte count 算準交給 VISA Read 等，最簡單也最穩。
