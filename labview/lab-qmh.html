QMH 與多迴圈架構：訊息怎麼在迴圈之間跑

這一頁把第六部分（A2 QMH、A3 四個迴圈、A7 結束順序）的架構圖變成會動的模擬。課文講「為什麼」，這裡讓你親手按按鈕，看訊息卡片怎麼排隊、怎麼在迴圈之間飛。

QMH（Queued Message Handler）有兩個迴圈：上面的 Event 迴圈平常停在 Event 結構等使用者，按鈕一按就把它變成一張訊息卡片 Enqueue 進佇列；下面的訊息處理迴圈每一圈 Dequeue 一張，用 Case 結構選對應的那一頁來做。處理到一半也可以再 Enqueue 新訊息給自己（藍色卡片），例如 Init 做完接著排 Read PLC，Read PLC 做完再排 Update UI。程式一開始，佇列裡已經先放了一張 Init。

訊息處理迴圈第 0 圈

對照：同樣的按法，簡單狀態機會怎樣？

簡單狀態機只有一個迴圈，Shift Register 只存「下一個狀態」一格。這裡假設它跟課文 A2 的表一樣只在 Idle 讀按鈕：忙的時候按下的 Latch 按鈕會先「卡在 True」，回到 Idle 那一圈才一起被讀，可是一圈只能決定一個下一狀態，其他的就沒了。

QMH 的重點：① Event 迴圈只負責「把事情說出來」，所以按鈕永遠立刻有反應；② 佇列先進先出，連按好幾個按鈕，訊息全部排隊，一個都不會被蓋掉；③ 處理迴圈送給自己的訊息也是排到佇列尾端，所以會排在使用者早就按下的訊息後面，要插隊（例如緊急的 Exit）可以用 Enqueue Element at Opposite End；④ 訊息用字串最簡單，可是打錯字不會報錯，只會掉進 Default 頁；用 Enum（做成 Type Def）就不可能打錯，資料欄位還可以直接帶數值，不用自己把字串拆開。A2 的 Decode_Cmd 用 Dequeue timeout 0，是因為那個狀態機要一直輪詢感測器；這一頁的訊息處理迴圈沒訊息就沒事做，所以停在 Dequeue 等（timeout -1）。

這是 13_PLC 的 Host_Main 縮小版：① MES 迴圈、② 通訊迴圈、③ UI 迴圈、④ 檢測迴圈同時在跑。只有通訊迴圈跟 PLC 講話：別人要寫 PLC，就把「位址×65536＋值」的 U32 卡片丟進寫入佇列，通訊迴圈每圈用 Flush Queue 一次全部拿走寫進去；它讀到的狀態用 Notifier 廣播，UI 和檢測迴圈都拿得到最新一筆；檢測結果另外丟進 MES 佇列給 MES 迴圈慢慢上傳。注意 UI 和檢測迴圈沒有自己的佇列，它們是「等通知」，不是「等訊息」。

看這幾件事：① 按 Start 之後，卡片走的路線是 UI 迴圈 → 寫入佇列 → 通訊迴圈 → PLC，UI 迴圈自己從來不碰 PLC；② 檢測迴圈花 1.4 秒檢測時，通訊迴圈照樣每 100 ms 一圈，心跳 D520 一直在變，畫面也一直更新；③ 檢測完一次放兩張卡片（先 D510 結果、再 D511=1 完成），佇列先進先出，所以 PLC 一定先收到結果；④ 勾「MES 斷線」，生產照跑，上傳失敗的資料留在 MES 迴圈的待送清單裡，取消勾選後會補送；⑤ 勾「PLC 回覆變慢」，UI 迴圈等不到新通知就逾時、繼續顯示舊值（課文 A6 的 Select：timed out ? last : notification），迴圈本身不會停；⑥ 按「讀 PLC 狀態」不會產生任何卡片：通訊迴圈本來就每圈在讀，UI 只要拿 Notifier 的最新一筆。E-Stop 在這裡是課文裡訓練用的故障注入開關（寫 D550 bit0），真正的急停迴路在 PLC 和硬體那一側。

多迴圈程式最難的是「怎麼一起停下來」。Host_Main 沒有 Stop 按鈕給每個迴圈，而是：UI 迴圈決定結束 → 釋放參照 → 正在等這個參照的迴圈收到錯誤 → 迴圈的停止條件接錯誤線 → 停。選一種做法，按 ▶ 讓機台生產（會自動按 Start），等檢測迴圈在檢測時按 Exit。

遺失或沒做到的事

課文 A6、A7 的順序：① 按 Exit，UI 迴圈閂鎖住「要離開」，第一次只送 D100=2（做完這顆再停），記下時間；② UI 迴圈繼續跑，直到 PLC 回到 30 Idle、或進入 900 以上的警報、或斷線、或已經過 20 秒；③ UI 迴圈停；④ Release Notifier 的 error in 接 UI 迴圈的錯誤線，所以這時才執行 → 通訊迴圈的 Send Notification 出錯而停、檢測迴圈的 Wait on Notification 收到 1122 而停；⑤ 接著 Release 寫入佇列；⑥ 檢測迴圈的錯誤線接到 Release MES 佇列 → MES 迴圈的 Dequeue 收到 1122 而停；⑦ 最後 Host_Exit 結批、關伺服、關相機。前面板 Exit Error 顯示 1122、來源 Dequeue Element，是預期的關機痕跡，不是故障。
錯誤線在這裡的用途是排順序：LabVIEW 照資料流執行，Release 只接了參照、沒接 error in，就會在程式一開始輸入到齊時立刻執行。
