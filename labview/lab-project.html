專案實驗室

13_PLC 這種大程式不會只有一個 VI。這裡看三件事：專案檔 .lvproj 到底存了什麼、資料要傳給另一個程式或另一台電腦時用哪一種變數、最後怎麼包成在沒裝 LabVIEW 的產線電腦上能跑的執行檔。

左邊是 Project Explorer 看到的樣子，右邊是硬碟上真正的資料夾。藍線是專案記住的路徑。專案檔只是一張「清單」，記的是檔案在哪裡，VI 本身還是存在硬碟上各自的位置。

Virtual Folder（紫色）只存在專案裡，用來分類，硬碟上沒有這個資料夾，裡面的檔案還是在原本的位置。Auto-populating Folder（青色）跟硬碟上的一個資料夾同步，硬碟多了或少了檔案，專案裡也跟著變。想搬檔案又不想讓專案找不到，在 Project Explorer 的 Files 頁籤裡搬，LabVIEW 會一起更新記住的路徑；在檔案總管直接搬，專案還記著舊路徑（本頁用 ⚠ 示意找不到的項目）。

產線電腦上的通訊 VI 每秒讀一次 PLC 的 D300（右軸位置），想讓其他程式也看得到。選一種變數，按「寫入」，看值傳得到哪裡。

Global Variable 是一個只有前面板的特殊 VI（File ▸ New 裡選 Global Variable），只在同一個應用程式裡的 VI 之間共用。Shared Variable 在專案裡建立，放在一個 Library（.lvlib）裡：Single-Process 的範圍和 Global 一樣，只在同一個應用程式；Network-Published 透過 Shared Variable Engine 發佈到網路上，要先 Deploy，同一台電腦的其他程式和別台電腦都讀得到。不管哪一種，多個地方同時寫一樣有競爭問題（見變數實驗室），命令類的資料還是用 Queue。

在 Project Explorer 的 Build Specifications 上右鍵 ▸ New ▸ Application (EXE)，填設定、按 Build。13_PLC 的主程式會用 VI Server 動態載入一個外掛 Host_Plugin_A.vi（方塊圖上沒有直接放它）。（本頁的 Host_UI.vi、Host_Log.vi、Host_Plugin_A.vi 是示範用的名稱，課程的 13_PLC 檔案裡沒有這幾個 VI。）

拿到產線電腦執行

Startup VI：執行檔一打開就執行的 VI。它直接呼叫的 SubVI，Application Builder 會自己找出來一起包。Always Included：方塊圖上看不到、執行時才動態載入的 VI，Builder 找不到，要手動加進來。執行檔只包含你的程式，不包含 LabVIEW 本身：目標電腦要裝和建置版本相同（位元數也要相同）的 LabVIEW Run-Time Engine，用到 VISA、DAQmx 也要裝對應的驅動。可以再建一個 Installer 建置規格，把這些一起包成安裝程式。

LabVIEW 為 NI 之商標。本站為獨立製作，與 NI 無關；專案與建置行為以 LabVIEW 說明文件為準。
