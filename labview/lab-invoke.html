方法節點實驗室：叫元件做事、叫別的 VI 做事

屬性節點（Property Node）是讀寫元件的特性，像名詞：數值、顏色、Disabled。方法節點（Invoke Node）是叫元件做一件事，像動詞：恢復預設值、拍一張圖、把圖表存成檔案、執行一個 VI。兩個都要接一條參考（refnum）告訴它「對誰」。屬性節點的用法見 屬性節點實驗室，這裡專講方法和 VI Server。

龍門人機的設定頁。選一個元件，再選要用的節點，按執行。看看屬性節點和方法節點各做了什麼。

GT_Setup.vi 前面板（簡化）

分辨的方法：屬性可以讀（從節點右邊出來一個值）或寫（從左邊給一個值），寫完那個特性就變成那樣；方法是一個動作，執行一次做一次，可能要給參數、可能傳回結果。例如 Reinitialize To Default 把元件恢復成「存檔時的預設值」；Get Image 傳回元件長相的影像資料（可以設 Image Depth）；Export Image 不是每個元件都有，是 Waveform Chart、Waveform Graph 這類圖表的方法：把圖表存成圖檔，可以選檔案類型、路徑、要不要隱藏格線、要不要直接覆蓋舊檔（前面板沒有載入時不會產生檔案）。Key Focus 是屬性，不是方法。清除圖表則是寫 History Data 屬性（寫一個空陣列），它是屬性不是方法。

每一個前面板元件都屬於 VI Server 的某個類別，類別有上下層：下層繼承上層全部的屬性和方法，再加上自己才有的。點樹上的類別，看它能用哪些（顏色表示是哪一層定義的）。

    接得上嗎？把元件的參考接到 SubVI 的 refnum 輸入

    SubVI 的參考輸入用 Control Refnum（在前面板放一個 Refnum 控制項，右鍵選類別）。選得越上層，能接的元件越多，但只能用上層的屬性；選得越下層，能用的越多，但只有那一類接得上。下層的參考接到上層的輸入可以直接接；反過來要先用 To More Specific Class 轉，型別不對時它會出錯，要接錯誤線處理。

    This VI 是「這個 VI 自己」的參考。從它讀 Front Panel 屬性得到前面板的參考，再讀前面板的 Controls[]，就得到前面板上所有控制項、顯示元件參考的陣列。接進 For Loop 自動索引，一個一個處理：不用自己一個一個拉參考。

    GT_Manual.vi 前面板（簡化）

    Controls[] 給的是直接放在面板上的控制項和顯示元件，所以常要先讀 Label.Text 之類的屬性挑掉不想改的。叢集（Cluster）只回傳叢集本身，不會展開成裡面的元素；框線、文字這些裝飾不在 Controls[] 裡（在另一個 Decorations[] 屬性）。陣列裡每個元素的型別是通用的 Control 參考，只能直接用 Control 這一層的屬性和方法（Disabled、Reinitialize To Default 都是）；要改 Numeric 才有的屬性，要先轉成更下層的類別。

    主程式要算「X 軸移動一段距離要多久」，計算寫在另一個 VI（Calc_MoveTime.vi）裡，前面板有 Distance、Speed 兩個輸入和 Time 一個輸出。用 VI Server 從主程式叫它：開參考 → 設輸入 → 執行 → 讀輸出 → 關參考。

    Calc_MoveTime.vi 前面板（被叫的 VI）

    主程式拿到 Time–記憶體裡還開著的參考0

    Open VI Reference 的 vi path 接路徑（或已經在記憶體裡的 VI 名稱），傳回這個 VI 的參考。Control Value ▸ Set 用控制項的名稱（標籤文字）寫值，值的型別是 Variant，任何型別接上去都會自動轉成 Variant。Run VI 用前面板目前的值執行：Wait Until Done 預設是 TRUE，會等它跑完才往下；Auto Dispose Ref 預設是 FALSE，參考要自己關。Control Value ▸ Get 傳回 Variant，要用 Variant To Data 指定型別轉回來，型別不對就出錯（還有 Get All 一次讀全部）。最後 Close Reference：每開一個就關一個。沒關的參考，在開它的 VI 結束之前 LabVIEW 都沒辦法釋放；在迴圈裡開了不關，長時間執行就越積越多。
