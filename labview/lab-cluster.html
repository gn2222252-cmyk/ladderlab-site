叢集實驗室

第 8 課做了 GT_Status，第 11 課講了錯誤線。這裡把它們「動」起來：元素怎麼進出叢集、叢集順序改了會出什麼事、Type Def 改一處為什麼全部跟著變，以及錯誤叢集怎麼沿著線一路傳到最後。後面四個分頁再看陣列和叢集怎麼互轉、叢集怎麼直接做運算、面板位置和叢集順序的差別，以及 Tab Control。

一台雙龍門的「機台狀態」叢集，裡面有 5 個不同型別的元素。選一個函式，按「執行」看元素怎麼走。再按下面的「改叢集順序」，比較用位置（Bundle／Unbundle）和用名字（By Name）的差別。

改叢集順序（Reorder Controls In Cluster）：

同一個「機台狀態」在三個 VI 裡傳來傳去：GT_Parse 解析 PLC 回應做出狀態 → GT_Monitor 檢查異常 → GT_Main 顯示。勾選哪些 VI 用 Type Def（連到 MachineStatus.ctl），再按「在 .ctl 加一個元素」，看誰跟上、誰斷線。

方塊圖上，連到 Type Def 的叢集常數和端子，左上角有一個小黑三角形（本頁標題前的 ◤）。沒有連的只是「長得一樣的複本」，.ctl 改了它不會知道。這裡加了一個元素，兩邊的元素數量就不同，接在一起會斷線，整個 VI 不能執行。

和 PLC 通訊的標準寫法：錯誤線把每個節點串起來。在任一個節點選「注入錯誤」，按「執行」，看錯誤叢集（黃色雙線）怎麼往後傳。

目前在錯誤線上的叢集
記住三件事：① 收到 status = True 的節點不做事，把同一個錯誤原封不動傳下去，所以最後看到的永遠是「第一個」錯誤。② Close 類的節點（VISA Close、Close File、Close Reference）例外：不管有沒有錯誤都會執行，資源才不會一直被占著。③ 警告是 status = False、code ≠ 0，不會讓後面的節點跳過；Simple Error Handler 的 type of dialog 預設是 1（OK message），只顯示錯誤；要連警告一起顯示，選 3（OK message + warnings）或 4。本頁只畫出錯誤的對話框。

左右兩台 PLC 平行通訊，兩條錯誤線最後要變成一條，才能交給同一個 Simple Error Handler。Merge Errors 從最上面的輸入開始找：先找第一個「錯誤」；都沒有錯誤，才找第一個「警告」；也沒有警告，就輸出沒有錯誤。

Merge Errors 不會把兩個錯誤「加起來」，只挑一個傳出去，其他的就看不到了。所以重要的那條線接在上面。想把錯誤真的丟掉，用 Clear Errors.vi，而且只用在「我知道會錯、也處理好了」的地方，例如斷線後要重連。

陣列是「同型別排一列」、叢集是「綁成一捆」。下面四個函式在兩者之間轉換。選一個，按「執行」看格子怎麼走。

叢集裡都是數值時，可以直接接到 Add、Multiply 這些數值函式，每個元素各算各的。例子：右軸、左軸、Z 軸三個位置綁成一個「位置」叢集，加上一個「補正量」。

+

叢集接數值函式的條件：元素都是數值（或數值陣列）；兩個叢集相加時，元素的數量要一樣、一個對一個。叢集也可以和一個純量運算，純量會和每個元素各算一次。叢集裡有字串、布林這類不能相加的元素，線就斷了。

前面板上，叢集裡的元素放在哪裡，和它是第幾個（叢集順序）是兩回事。拖動元素只改位置；要改順序得用叢集邊框右鍵 ▸ Reorder Controls In Cluster…。順序決定 Unbundle 從上到下的輸出、Bundle 從上到下的輸入（接錯的後果在第一個分頁）。

Tab Control 只是把前面板分成幾頁排版。所有頁上的控制項同時存在，方塊圖上每個端子都在，不管現在顯示哪一頁，程式都讀得到。Tab Control 自己也有一個端子，它的值是「目前顯示哪一頁」，型別像 Enum，接到 Case 結構時頁籤就是分頁名稱。
