Enum 實驗室

雙龍門的「運轉模式」有四個選項：手動、自動、原點復歸、急停。做成下拉選單有兩種元件：Enum 和 Ring。看起來一樣，用起來差很多。這裡用動畫比較它們接到 Case 結構、遇到新增選項、當狀態機狀態時的差別。

在前面板選一個模式，看同一個選擇接到 Enum 和 Ring 兩邊各發生什麼。兩種元件底下都是整數，差別在「文字算不算型別的一部分」。

運轉模式：

Enum 的項目文字跟著線走，所以 Case 頁籤直接寫 "原點復歸"，右鍵還能 Add Case for Every Value 一次補齊每個值。Enum 的值固定是 0、1、2…連續編號。Ring 的文字只是顯示用，線上只有數字，Case 頁籤也只能寫數字；好處是值可以自訂，適合對應硬體代碼（例如 PLC 的模式暫存器 10、20、30、99）。

MachineMode.ctl 是 Enum 的 Type Def。現在要加第五個模式「保養」。三個 VI：GT_Main 用 Type Def 的 Enum 接 Case（四頁，沒有 Default）；GT_Panel 的 Enum 常數是當初複製的，沒連到 Type Def；GT_Old 是舊程式，用 Ring 接 Case（0～3 和 Default），有人在它的 Ring 裡手動加了「保養 = 4」。

這正是 Enum + Type Def 的價值：加了新值，漏寫的地方在編輯時就斷箭頭，逼你處理。Ring 是數字，數字的 Case 通常靠 Default 接住沒列出的值，新值就默默走 Default，執行時才發現機台沒反應。沒連 Type Def 的 Enum 常數只是舊清單的複本，不會自己長出新選項。

同一個 .ctl 用在兩個 VI 的前面板。左邊兩個實例連到一般的 Type Def，右邊連到 Strict Type Def。修改 .ctl，或在使用的地方自己改外觀，看哪些會同步。

Type Def

Strict Type Def

一般 Type Def 只同步資料型別：Enum 的項目是型別的一部分，所以兩種都會同步；顏色、大小這類外觀不同步，每個地方可以各自調整。Strict Type Def 連外觀也同步，使用的地方不能自己改外觀；Ring 的項目文字不是型別的一部分，只有 Strict 才會跟著 .ctl 更新。

一個簡單的狀態機：待機 → 原點復歸 → 自動 → 待機…，下一個狀態放在 Shift Register 裡。左邊用字串當狀態，右邊用 Type Def 的 Enum。在字串版本的「待機」頁裡，下一個狀態的常數打錯字會怎樣？

字串狀態

Enum（Type Def）狀態

字串 Case 要有 Default 接住沒列出的字串（字串有無限多種），打錯字的狀態就掉進 Default，程式照跑、不報錯，機台卡在原地，要看 log 才知道。Enum 常數只能從下拉選單選，根本打不出不存在的狀態；Case 頁籤也只能是清單裡的值。這就是為什麼狀態機的狀態用 Type Def 的 Enum。
