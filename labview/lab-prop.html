屬性節點實驗室

第 18 課用 Disabled 把手動按鈕反灰，CLAD C8 講了 Property Node 和 Control Reference。這裡讓你自己下指令：屬性怎麼寫進前面板、寫值時事件會不會跟著觸發、怎麼在 SubVI 裡一次改主畫面的一整組按鈕。

選一個前面板元件和屬性，決定要「寫」還是「讀」，按執行。寫入時，值從左邊流進屬性節點再改到前面板；讀取時，值從前面板流進節點、從右邊出來。前面板上的按鈕可以真的按，試試看 Disabled = 1 和 2 有什麼不同。

屬性節點放下時預設是讀（端子在右邊，往外輸出）；右鍵 ▸ Change To Write 才變成寫（端子在左邊，往裡輸入）。同一個節點可以往下拉長放好幾個屬性，執行時由上往下一個一個做。Disabled 有三個值：0 Enabled、1 Disabled（看起來正常但按不動）、2 Disabled and Grayed Out（反灰也按不動）。顏色這類屬性的實際名稱和位置依元件而不同（通常在 Text、Numeric Text 這些項目底下），本頁簡化成一個「顏色」。

方塊圖上的 Event 結構有一頁「速度設定：Value Change」。用不同方法把速度設定改成新的值，看這一頁會不會執行。也可以直接在前面板的數值上按 ▲▼ 或改數字（等於使用者操作）。

Value Change 事件只由使用者在前面板操作或寫 Value (Signaling) 屬性產生。寫 Value (Signaling) 時，就算寫進去的值和原本一樣也會產生事件；只想在值真的改變時觸發，就先比較再寫。Local Variable、Property Node 的 Value、寫 Indicator 端子都不會產生事件。要「用程式改值、又要事件那一頁跟著跑」，才用 Value (Signaling)；平常只是更新顯示，用端子最好。

隱含 vs 明確屬性節點

隱含（implicit）：在同一個 VI 的元件上右鍵 ▸ Create ▸ Property Node。沒有參考輸入，標題是元件的名字，只能改這個 VI 自己的元件。

明確（explicit）：從選盤放 Property Node，左上角接一條參考線。標題是類別名稱（例如 Boolean），參考從哪來就改哪個元件，所以能放在 SubVI 裡。
