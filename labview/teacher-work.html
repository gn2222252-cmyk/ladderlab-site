W6　產線功能測試站（Judge.vi） 看課文

帶走

  • 上下限放在檔案（limits.csv），程式裡不寫數字；改了要走核准。
  • 先證明「量得準」再寫程式：量測散佈要遠小於公差。
  • 任何一條結束路徑（完成、FAIL、儀器錯誤、按停止）都要先關負載、再關電源。

評分重點

    • 常見錯誤

    • In Range and Coerce 預設不含上限，忘了勾，剛好等於上限的板子會判 FAIL。發現：驗收 T9 用一片剛好等於上限的板子（或暫時把上限改成量到的值）。
    • 序號規則少了 ^ 和 $，前後多出字元的序號也會過。發現：驗收 T1 打一串像商品條碼的數字。
    • 只在「測完」那條路斷電，FAIL 或 DMM 逾時時電源還開著。發現：驗收 T7 勾「DMM 的 USB 線鬆了」，看電源和負載是不是都 OFF。
    • 把 ERROR 算成 FAIL，或把它算進良率的分母。發現：看 CSV 的結果欄有沒有 ERROR 這個值。
    • 學生把 [0-9] 改寫成 \d，而字串常數又開了「'\' Codes Display」，反斜線被當成跳脫碼。課文用 [0-9] 就是為了避開這件事。發現：序號格式明明對卻一直被擋時，打開常數看它的顯示模式。

    課堂建議

    • 模擬測試站先用預設（不勾 DMM 鬆、不勾工程模式）測一片良品，再照驗收表 T1～T8 一條一條做。
    • 先問「T01 無載電流越小越好，為什麼還要下限 5 mA？」，答案在驗收 T6「治具沒壓好」。
    • 分組討論：「電源和負載自己都能量電壓，為什麼還要買一台 DMM？」可以接到四線量測和 W14。

    要實機或軟體確認

    • 電源、負載、DMM 的 SCPI 指令以各儀器的程式手冊為準。
    • In Range and Coerce 的 Include upper limit 在 LabVIEW 2018 的右鍵選單。

    W7　設備稼動監控（Count.vi） 看課文

    帶走

    • 監控程式只讀不寫 PLC；遠端啟動機台的顧慮是現場可能有人。
    • 16 位元計數器會繞回 0：用 U16 相減再累加；第一次讀取和讀取失敗的那一圈都不算產量。
    • 通訊中斷的時間記成「不知道」，不能算成停機。

    評分重點

      • 常見錯誤

      • 讀取失敗時 Index Array 給 0，照樣相減，差值繞回成六萬多包，恢復時又再算一次。發現：Count.vi 的 Run 步驟「拔線再接回」，看產量有沒有跳。
      • 計數放在一般型的 D 暫存器，PLC 斷電或 STOP 就清成 0。FX3S 的 D0～D127 是一般型，D128～D255 才是停電保持型，所以課文用 D200 起。發現：問學生計數放在哪個 D、PLC 重開會不會歸零。
      • 把通訊中斷的時間算成停機，可用率被拉低。發現：模擬勾「通訊線拔掉」一段時間，看時間軸那一段是不是黑色。
      • GX Works2 顯示 −32768、LabVIEW 讀到 32768，就以為有一邊錯了。發現：用這一課的「問自己」讓學生解釋：兩邊是同一個 16 位元，一邊看成有號、一邊看成無號。
      • 效能算出來超過 100 %，沒有追問原因。發現：問「標準週期是誰給的」。

      課堂建議

      • 模擬先不勾「通訊線拔掉」「計數從 65 500 開始」，跑完一個班看 OEE；再一項一項勾起來比較。
      • 先問「監控程式為什麼只讀不寫？」，用廠長那句「順便讓我在辦公室按一下就能開機」開頭。
      • 分組算小測驗的可用率、效能、OEE，對答案。

      要實機或軟體確認

      • 通訊埠、鮑率、站號要和 PLC 一致（L12～L14 的設定）。
      • FX3S 停電保持區的範圍，以三菱 FX3S 程式手冊為準。

      W8　接手舊程式（T03_Judge.vi） 看課文

      帶走

      • 動手之前先做三件事：複製一份放進版本控制、用已知的板子跑一次留基準、讀懂流程。
      • 一次只改一件事，每改一次跑回歸測試。
      • 看不懂的東西（例如沒註解的 Wait 3000 ms）先問、先實驗，搞懂了再寫註解，不能直接刪。

      評分重點

        • 常見錯誤

        • 「順手」刪掉看不懂的 Wait，每片快 3 秒，結果某一類板子判錯。發現：回歸測試台勾 D，看哪一類板子的結果變了。
        • 一次改好幾項才跑回歸測試，出現差異時不知道是哪一項造成的。發現：要學生說出每一項修改各自造成的差異。
        • 舊程式 DMM 讀不到時判 PASS：錯誤沒處理，區域變數還是上一片的值。發現：基準測試時用「DMM 線鬆了」那一類板子（B5）。
        • 用新版 LabVIEW 存檔，2018 打不開。發現：交作業時用 2018 開一次；要用 Save for Previous Version。
        • 把 Wait 放在量 T03 那一格，註解卻寫「等電源上升」：程式和說明對不上，接手的人會改錯。發現：對照程式裡 Wait 的位置和註解寫的用途。

        課堂建議

        • 回歸測試台先一項都不勾，跑出基準；再一次勾一項（A～E）。
        • 先問「基準跑出來，B5（DMM 線鬆了）竟然是 PASS，要現在就修嗎？」
        • 分組找出舊程式那一格的四個問題，比哪一組找得多。

        要實機或軟體確認

        • VI 是二進位檔，git 看不出改了哪裡。課文的 tip 提到兩件事：勾「Separate compiled code from source file」；Tools ▸ Compare ▸ Compare VIs 只有專業版才有。學校的 LabVIEW 是哪一版、有沒有這個工具，要先確認；沒有的話，就在提交訊息寫清楚改了什麼。

        W9　測試結果進資料庫 看課文

        帶走

        • 兩個表：tests 一次測試一列、meas 一項量測一列；每筆量測都存當時的 lo、hi 和程式版本。
        • 序號是外面來的字串，要用參數化查詢，不能用 Format Into String 拼進 SQL。
        • 資料庫斷線時產線照常測：先存本機，另一個迴圈恢復後補傳，不重複、不遺失。

        評分重點

          • 常見錯誤

          • 只存量測值，不存當時的上下限；上下限改過以後，查不出當時用什麼標準判的。發現：問「這一片當時的上限是多少」。
          • 讓資料庫自動編號，斷線補傳時對不起來。發現：驗收 T3 拔網路線測 10 片再接回，看資料庫是不是剛好多 10 筆。
          • 上傳中途斷線，留下「有 tests 沒有 meas」的半筆資料。發現：驗收 T4；要用交易（Begin、Commit／Rollback）。
          • 序號用字串拼進 SQL。發現：讓學生解釋「特殊字元或惡意輸入會變成別的 SQL 指令」。
          • 查詢結果靠程式在背後再過濾一次，SQL 本身看不出來，別人照抄 SQL 會得到不一樣的答案。發現：SQL 主控台裡每一個查詢的結果，都要能從那句 SQL 本身解釋得通。

          課堂建議

          • SQL 主控台先照順序跑 ① ② ③，再問「你要怎麼回覆品保？」
          • 暫存模擬先不勾「資料庫斷線」跑一次，再勾起來比較。
          • 分組討論：「為什麼 test_id 要由測試站自己產生？」

          要實機或軟體確認

          • Database Connectivity Toolkit 的 VI 名稱和流程。
          • 資料庫主機、帳號權限由 IT 給；測試站帳號只要寫入和查詢自己的表。

          W10　治具開短路測試（Scan.vi） 看課文

          帶走

          • 用一個參考電阻和一個 AI 通道量電阻：Rx ＝ 1000 × V ÷（Vs − V）。
          • 一次只接通一顆繼電器（one-hot），切換後要等穩定；等多久要用實驗決定。
          • 治具自檢點（P8）不對，就先修治具，其他點的結果都不可信。

          評分重點

            • 常見錯誤

            • Wait 和 DAQmx Write 並排放，沒有資料相依，等不到。發現：模擬把等待設 0 ms，好板子也有好幾點 FAIL。
            • 上一顆繼電器沒放開，兩點並聯，兩點都量錯。發現：模擬勾「程式寫錯：上一顆沒放開」。
            • 開路時 V 比 Vs 大一點點，分母變負，算出負電阻，開路被判成短路。發現：拿一片開路的板子，看那一點是不是顯示 +Inf。
            • 換成輸入阻抗低的 DAQ，高阻值的點會量錯。發現：模擬勾「換成 AI 輸入阻抗只有 144 kΩ 的低價 DAQ」。
            • 板子通電時做開短路測試。發現：小測驗「開短路測試時板子應該？」答案是不通電。

            課堂建議

            • 模擬先用預設（10 ms、不勾兩個「寫錯」）跑好板子，再把等待改成 0 ms。
            • 先問「P16 空腳量到開路是 PASS，P7 量到開路是 FAIL，為什麼？」
            • 分組做驗收 T3：2、5、10 ms 各跑 10 次，找最短的安全等待時間。

            要實機或軟體確認

            • 繼電器的動作時間看規格書，再實際試 2、5、10、20 ms。
            • 所用 DAQ 的 DO 條數、AI 輸入阻抗和解析度。
            • USB DAQ 開機時 DO 的狀態，會不會讓繼電器全部吸合。

            W11　配方與警報（Alarm_TempLow.vi） 看課文

            帶走

            • 作業員只能選配方，工程師才能改；配方存檔前和讀檔時都要檢查範圍。
            • 下載到 PLC 後要讀回比對，一致才准啟動。
            • 警報要有遲滯、延遲、栓鎖和確認：還在警報中按「確認」，燈繼續亮，恢復後才熄。

            評分重點

              • 常見錯誤

              • 只靠 3 °C 遲滯，雜訊約 6 °C 時還是會叫好幾次：遲滯帶要比雜訊的峰對峰值大。發現：警報模擬只勾遲滯，數警報發了幾次。
              • 以為 JSON 少一個欄位只是「那個欄位讀不到」：Unflatten From JSON 遇到少了叢集要的欄位（改了標籤或加了參數），會回錯誤，整筆讀不進來。發現：用記事本刪掉 recipes.json 的一個欄位再開程式。
              • 「確認之後燈什麼時候熄」在規格、程式、操作說明裡寫得不一樣。發現：照規格 A1、A2 跑 Run 步驟，三份文件對一次。
              • 保護機台的 Interlock 只寫在 LabVIEW。發現：問「電腦當機時誰來擋？」答案是 PLC。
              • 範圍檢查只在存檔時做，讀檔時不做。發現：驗收 T3 用記事本把壓力改成 9 再開程式。

              課堂建議

              • 警報模擬先三個都不勾（遲滯、延遲、栓鎖），看警報洗版；再一個一個勾。
              • 先問「下載到 PLC 為什麼要讀回來比對？寫進去不就好了嗎？」
              • 分組討論課文那段話裡的兩個問題（作業員改錯參數、警報洗版），各自真正的原因。

              要實機或軟體確認

              • 在 LabVIEW 2018 讀一個少了一欄的 JSON，看錯誤碼和輸出。
              • 實機上常是 PLC 算出警報位元，LabVIEW 讀來顯示、確認、記錄。PLC 那一端怎麼做，要和 PLC 程式對齊。

              W12　老化燒機記錄（History.vi） 看課文

              帶走

              • 長時間程式的四個敵人：記憶體一直長、資料只在記憶體、通訊斷了就停、電腦自己重開。
              • 量測和存檔分開（生產者／消費者），每筆寫完就 Flush，定時換檔。
              • 時間用時間戳記，不用「第幾圈 × 10 秒」推算。

              評分重點

                • 常見錯誤

                • 每筆都 Build Array 接到 Shift Register、沒有上限，記憶體一直長。發現：驗收 T1 把間隔改成 0.1 秒跑 1 小時，看工作管理員。
                • 跑完才存檔，第 6 小時當掉資料全沒了。發現：驗收 T3 用工作管理員強制結束，看檔案有沒有到最後一筆。
                • 通訊錯誤就停整支程式。發現：驗收 T2 拔掉儀器 USB 1 分鐘再插回。
                • 以為「Wait 10000 的一圈 ＝ 讀儀器時間 ＋ 10 秒」：Wait 和讀儀器並排時是取長的那個，而且一圈變長之後全部往後推。要固定間隔，用時間排程（下一次 ＝ 上一次 ＋ 10 秒）。發現：用 Tick Count 量幾圈的實際間隔。
                • 斷電時「最多損失最後一筆」不一定成立：還在作業系統快取裡的資料可能不見，要靠 UPS。發現：問學生 B2 那句的前提是什麼。

                課堂建議

                • 模擬先用第一組做法（不限長度、跑完才存、出錯就停）跑一次，中途按「通訊斷」和「電腦當機」。
                • 先問「10 台 × 2 個數 × 2880 筆才幾百 kB，為什麼記憶體會一直長？」
                • 燒機前電腦要設定的事（課文的 warn），可以和 W19 一起講。

                要實機或軟體確認

                • 長時間跑時，用工作管理員看記憶體曲線。
                • 熱電偶模組要有冷接點補償（W2）。

                W13　簡易 AOI（Judge_Washer.vi） 看課文

                帶走

                • AOI 的成敗大半在光源：量外徑用背光，光源變暗時固定門檻會誤判。
                • 像素換 mm 要用校正片，校正和量測要用同一種量法。
                • 和 PLC 交握：先把 Result 放好，再設 Done；看到 PLC 把 Trigger 拉回 0 之後，才清 Done。

                評分重點

                  • 常見錯誤

                  • 光源變暗後背景比門檻還暗，背景被當成工件。發現：模擬把光源調到 50 %，固定門檻 128 不變。
                  • 只量外徑、不看面積比，缺一小角時外框寬度可能不變。發現：用缺角的 NG 品測。
                  • DAQ 的數位線直接接 PLC 的 24 V I/O。發現：接線前先查兩邊的電壓準位。
                  • Done 和 Result 同時設，PLC 可能讀到上一片的結果。發現：問學生「Result 為什麼要在 Done 之前放好？」
                  • 只拿 OK 品調參數，沒有先收集 NG 樣本。發現：驗收 T1 的 OK 50 片、各種 NG 品各 10 片，每片過 3 次。

                  課堂建議

                  • 模擬先用預設（光源 100 %、門檻 128、不勾自動門檻），再把光源往下調。
                  • 先問「320 像素看 40 mm，一個像素是幾 mm？要量 ±0.2 mm 夠嗎？」
                  • 分組討論漏判和誤判哪個比較嚴重（課文的 note）。

                  要實機或軟體確認

                  • FX3S 的實際輸入濾波值。
                  • Vision Assistant 試用版能不能產生 LabVIEW 程式。

                  W14　現場除錯（FailRate.vi） 看課文

                  帶走

                  • 除錯順序：先把問題講清楚，先圍堵，再看已經有的資料，再做小實驗，最後才動手換東西。
                  • 突然變差，先查「那天改了什麼」（變更、保養紀錄）。
                  • 不能用放寬上下限來「解決」問題；修好要用數字確認。

                  評分重點

                    • 常見錯誤

                    • 一接到「很多 FAIL」就去換治具或放寬上下限。發現：問「你的資料說是哪一站、哪一項、從哪一天開始？」
                    • 門檻設太低（例如 5 %），正常的站一天會亮好幾次，很快就沒人理（W11 的洗版）。發現：Run 步驟先用 2 % 跑一陣子，看燈多常亮。
                    • 只看「好板子被誤判」，忘了「壞板子可能被放過」。發現：問課文那題「哪一種壞板子會被 ST02 放過？」
                    • 找到一個「看起來像」的原因就停：例如只換探針，卻解釋不了為什麼四線量測會受探針影響、為什麼是那一天開始。發現：問學生「四線量測下，負載探針磨損為什麼本來不影響 DMM 讀值？」
                    • FAIL 率只存在記憶體裡，程式重開就歸零。發現：問「明天開機時，最近 50 片從哪裡來？」答案是從 W9 的資料庫算。

                    課堂建議

                    • 除錯模擬先選「（先查，再決定）」，不要讓學生直接猜原因。
                    • 先問「這句話裡缺了什麼？去現場之前要先問清楚什麼？」
                    • 分組比較「FAIL 的板子拿到 ST01 重測」和「DMM 對調」各自證明了什麼。

                    要實機或軟體確認

                    • golden sample 連測、A/B 對調都要在實際的測試站上做，網頁只是模擬。

                    W15　特性曲線自動量測（Sweep.vi） 看課文

                    帶走

                    • 效率要量四個值：Vin、Iin、Vout、Iout；電壓用四線量在板子的端子上。
                    • 每一點要等到熱穩定再讀；輕載時輸入電流的準確度決定效率準不準。
                    • 報告要寫到別人能重做一次：條件、接線、儀器和校正日期。

                    評分重點

                      • 常見錯誤

                      • 電壓用兩線量在負載的端子上，Vout 少了導線壓降，重載效率偏低。發現：量測台只改「量電壓的位置」，看哪一段曲線變最多。
                      • 冷的板子從輕載快速掃到重載，重載效率偏高。發現：比較「每點等 1 秒、直接開始」和「暖機、等到穩定」兩組。
                      • 把 2D 數值陣列直接接到「表格」：表格是字串，線接不起來。要先用 Number To Fractional String 轉成字串。發現：方塊圖上那條線是斷的。
                      • Sweep.vi 的掃法和自己寫的規格不一樣（方向、點數、暖機）。發現：照規格逐條對 Sweep.vi。
                      • Load_Off.vi 遇到前面的錯誤就不做事，出錯時負載沒關。發現：小測驗「Load_Off.vi 有錯誤輸入時應該？」。

                      課堂建議

                      • 量測台先用最快、最省事的設定跑一次，再一項一項換成規格的做法，看曲線怎麼變。
                      • 先問「兩個人抄出來的曲線不一樣，可能是哪些原因？」
                      • 分組估算兩種做法各要花多少時間（課文的問自己）。

                      要實機或軟體確認

                      • 用 DMM 串在輸入線上量 Iin 時，負載電壓、檔位、保險絲。
                      • 實際的熱時間常數和暖機時間要量過才知道（模型是示意）。

                      W16　縮短測試時間 看課文

                      帶走

                      • 先量時間花在哪，再改；從最大塊的下手。
                      • 用 Flat Sequence 加 Tick Count 量每一步；Profile 視窗量不到等儀器的時間。
                      • 改完要證明品質沒變：GR&R 散佈沒變大、逐片比對沒有偏差、回歸測試結果相同。

                      評分重點

                        • 常見錯誤

                        • 拿掉一個測項來省時間。發現：時間表上選 G 會出現紅色警告。
                        • 輪詢到穩定判斷得太鬆（連續 2 次差 < 20 mV），讀值整批偏低，GR&R 看不出來。發現：用 R2b 的逐片比對。
                        • 把負載後的等待直接改成規格寫的最小值 0.4 秒：W8 量過回穩慢的良品要 1.2 秒。發現：對照 W8 回歸測試台的 B2 類。
                        • 把「開儀器」移到開始以後，不知道儀器中途重開機。發現：問每片要問哪個指令（*ESR? 的開機位元）。
                        • 已經用雙治具，瓶頸在人，還在改程式。發現：小測驗的最後一題。

                        課堂建議

                        • 時間表先全部用「現況」，看 18.2 秒花在哪；再一項一項改。
                        • 先問「先改哪一個最划算？」
                        • 分組討論「輪詢到穩定」的兩種判斷，為什麼一種可以、一種不行。

                        要實機或軟體確認

                        • 多個命令一次送、儀器並行，各廠牌支援的程度不同，以手冊為準。
                        • DMM 積分時間（PLC）對雜訊的影響要實測。

                        W17　上傳 MES（Upload.vi） 看課文

                        帶走

                        • 過站檢查在上電之前同步做；上傳結果可以在背景慢慢送。
                        • 逾時不等於沒收到：一定會重送，所以每筆要帶唯一鍵（test_id），MES 用它去重。
                        • 暫時錯誤（逾時、5xx）才重送，間隔越來越長；永久錯誤（4xx）停下來通知人。

                        評分重點

                          • 常見錯誤

                          • POST 沒設 Content-Type: application/json，MES 回 415 或把內容當成表單。發現：自己做的模擬 MES 收到的內容格式不對。
                          • MES 回 200 就刪暫存檔：前面的 Proxy 回一頁登入頁也是 200，資料就不見了。發現：Upload.vi 的 Run 選「200，但回的是 Proxy 的登入頁」。
                          • 失敗就一直重送、成功才測下一片，產線卡住。發現：上傳模擬選策略 ②，情境選「網路斷線」。
                          • 逾時後重送，MES 沒有去重，變成兩筆。發現：上傳模擬選「MES 很慢」、策略 ③ 或 ④，不勾 MES 的重複檢查。
                          • MES 回中文原因，LabVIEW 2018 顯示亂碼。發現：原因用代碼，測試站自己有代碼對中文的表（M1）。

                          課堂建議

                          • 上傳模擬先用 ① 跑四種情境，再換 ②、③、④，比較遺失、重複、卡產線。
                          • 先問「為什麼過站檢查要在上電之前做，不能丟給背景迴圈？」
                          • 分組比較「MES 改版，欄位名稱對不上」時，③ 和 ④ 的差別。

                          要實機或軟體確認

                          • HTTP Client 的 timeout 預設 10 秒；HTTPS 要用 ConfigSSL 設憑證。
                          • 整合測試 IT1～IT12 要和 IT 的測試用 MES 一起做。

                          W18　燒錄站（Flash.vi） 看課文

                          帶走

                          • 用 System Exec 呼叫命令列工具：路徑加引號、用非互動參數；System Exec 沒有逾時。
                          • 燒錄成功要看好幾道：檔案雜湊、寫入後驗證、return code、輸出文字、重開後讀回版本。
                          • 工具的失敗行為要自己故意做實驗記下來；發行清單的舊版標停用，不刪。

                          評分重點

                            • 常見錯誤

                            • 只看 return code。有些情況失敗了它還是 0（例如包在 .bat 裡）。發現：燒錄站模擬選「包在 .bat 裡，結束碼被蓋掉」。
                            • 工具跳出對話框，System Exec 一直等，測試站卡住。發現：模擬不勾 N。
                            • 以為讀回版本（B）就夠了，不看結束碼和輸出：驗證失敗的板子照樣重開、回報新版本，被放過。發現：燒錄站模擬裡找最少的關卡，每一種情況都要判對。
                            • 找 "Error" 太寬鬆，檔名或路徑裡剛好有這幾個字就誤判。發現：用帶冒號的 Error:。
                            • 燒完、驗證都過，沒讀回版本，不知道板子有沒有真的跑起來。發現：問「哪一種情況只有重開後讀回版本抓得到？」

                            課堂建議

                            • 燒錄站模擬先全部不勾，看七種情況各怎麼錯；再找最少的關卡。
                            • 先問「快閃記憶體壞了一格，為什麼沒開 -v 時會被判 PASS？」
                            • 分組寫燒錄 SOP 要寫的項目（課文的 note）。

                            要實機或軟體確認

                            • 燒錄工具的命令和輸出字樣是示意，以手冊、-h 和 E1 實驗為準。
                            • LabVIEW 2018 沒有內建 SHA256。

                            W19　部署到產線電腦（ConfigPath.vi） 看課文

                            帶走

                            • 設定檔、暫存資料夾、log 放 ProgramData，不放 Program Files。

                            評分重點

                              課堂建議

                              • 部署模擬先全部用第一個選項，跑一週；再一項一項改。
                              • 先問「C 為什麼這麼重要？它又不會讓任何問題消失。」

                              W20　XY 平台定位（XY_Move.vi） 看課文

                              帶走

                              • 開機一定要先回原點：PLC 的目前值只是送出去的脈波數，斷電後和實際位置無關。
                              • 互鎖（「Z 軸沒上升不准動 XY」）和軟體極限放在 PLC，LabVIEW 也檢查，當第二道；急停由安全繼電器的硬體接線切斷。
                              • 下命令的順序：確認待命 → 寫目標 → 最後寫命令 → 輪詢到完成或逾時 → 清命令。

                              評分重點

                                • 常見錯誤

                                • PLC 用 16 位元的 DRVA 只讀 D300，40000 個脈波變成 −25536，往反方向衝。發現：托盤模擬的「只寫低位字」情境。
                                • 以為 Split Number 拆出來的低位是 −25536：它輸出 U16，40000 拆出來就是 40000；−25536 是 PLC 用 16 位元讀的時候才會出現。發現：在 LabVIEW 用 Probe 看 Split Number 的輸出型別。
                                • 以為轉成整數會截掉小數，多加一個 Round To Nearest：LabVIEW 的 To Long Integer 本來就是四捨五入（C、Python 的 int() 才是截斷）。發現：小測驗「To Long Integer 把 39999.6 轉成？」
                                • 沒回原點時以為軟體極限擋得住。發現：問「軟體極限比的是誰以為的位置？」
                                • 步進馬達失步，PLC 和 LabVIEW 都不知道。發現：模擬勾 R（每盤結束回原點，檢查偏了多少）。

                                課堂建議

                                • 托盤模擬先五個保護都不勾，跑每一種情境；再一個一個勾。
                                • 先問「為什麼不用一個治具一次壓 4 片、4 台燒錄器同時燒？」
                                • 分組討論每一個保護該放在 PLC、驅動器、安全繼電器還是 LabVIEW（課文的分工表）。

                                要實機或軟體確認

                                • FX3S 的特殊暫存器編號要自己核對（課文的 note）。
                                • 課程實機的輸出型式（漏型或源型）和伺服驅動器的脈波輸入設定（research_W20）。
                                • FX3S-20M 的 I/O 點數夠不夠（課文的 I/O 表約 7 出，輸入更多）。

                                W21　LabVIEW 和 Python 並用（RunPy.vi、yield_report.py） 看課文

                                帶走

                                • 判定（PASS／FAIL）留在 LabVIEW；Python 做事後的統計和畫圖。
                                • 和別人的程式接，要先寫介面規格：命令列、一行 ASCII JSON、ok 欄位、結束碼、stderr。
                                • 規格要嚴格，接收要寬容，但不能寬容到把錯誤當成功：結束碼和 ok 都要看。

                                評分重點

                                  • 常見錯誤

                                  • 整段 stdout 當 JSON 解析，同事多印一行 loading... 就判失敗。發現：交班模擬不勾 L，看「多印一行」那一列。
                                  • 只看結束碼，或只看 ok。發現：交班模擬的「拿掉 try/except、結束碼 1」只有 R 抓得到。
                                  • 用一個叢集一次解析全部欄位：失敗時的 JSON 少了欄位，每一個 ok:false（連資料不足）都會讓 Unflatten 報錯。要分兩段解析。發現：RunPy.vi 的 Run 選「資料不足」，看解析錯誤的燈。
                                  • 字串常數開了「\ Codes Display」，\s 被換成空格，正規表示式抓不到最後一行。發現：常數的顯示模式；先用 Trim Whitespace 再比對。
                                  • Python 的 lo <= v <= hi 包含上限，In Range and Coerce 預設不包含。同一份規格翻成兩種語言，邊界可能不一樣。發現：用剛好等於上限的值，兩邊各跑一次。

                                  課堂建議

                                  • 交班模擬先七道檢查全部不勾，再一道一道加，目標是沒有「錯」和「卡住」。
                                  • 先問「在他電腦上跑得很好之後，你要先問清楚什麼？」
                                  • 分組對照 PY1～PY10 讀腳本，找出照規格的地方和要注意的地方；改一處（例如子群大小），記得更新 ver。

                                  要實機或軟體確認

                                  • 學校電腦的 LabVIEW 是 32 還是 64 位元（說明 ▸ 關於 LabVIEW）。Python Node 才需要對齊位元數，System Exec 不用。
                                  • LabVIEW 2018 的 Unflatten From JSON：報錯時 value 輸出什麼、遇到 \uXXXX 怎麼還原。
                                  • 學校或產線電腦上 import pandas, matplotlib 要幾秒；作業員帳號第一次跑會建 matplotlib 的字型快取。
                                  • 用 PyVISA（@py）連軟儀器電表 TCPIP0::127.0.0.1::5562::SOCKET，結尾字元要設成 \n。
