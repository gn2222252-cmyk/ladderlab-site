# 軟儀器：沒有真儀器，也能用真的 LabVIEW 練

一支 Python 程式，同時假裝四台儀器。
LabVIEW 用 VISA 連上去，就像連到真的儀器一樣收發。

想法和本專案的軟 PLC 一樣：把儀器的「對話方式」開在 TCP 埠上。

| 埠 | 代號 | 假裝的儀器 | 對話方式 |
|---|---|---|---|
| 5561 | gpd | GW Instek GPD-3303S 電源供應器 | 文字，一問一答 |
| 5562 | dmm | Keysight 34461A 數位電表 | SCPI，有錯誤佇列 |
| 5563 | bal | A&D FX-i 電子天平 | 預設不主動送，也可以連續送 |
| 5564 | dtb | 台達 DTB 溫度控制器 | Modbus RTU（位元組） |

行為和網頁的「儀器練習台」（`web/labview/instlab.html`）裡同名的儀器一樣。
先在網頁上試過，再到這裡用真的 LabVIEW 做一次。

## 這裡練什麼、不練什麼

TCP 沒有鮑率，也沒有同位。

- 這裡練：命令怎麼下、結尾字元、回覆長什麼樣子、逾時、錯誤處理。
- 這裡不練：鮑率與同位設錯會怎樣。那個請到網頁的儀器練習台練。

## 怎麼啟動

只需要 Python 3，不用裝任何套件（用 3.12 測過）。

```
python softinst/soft_instruments.py
```

視窗會列出四台的 VISA 資源名稱，然後一直開著。
之後每條連線收到、送出的位元組都會印出來，`\r` `\n` 會畫出來，方便對照：

```
[gpd 127.0.0.1:53211] 收到   6 個位元組  *IDN?\n
[gpd 127.0.0.1:53211] 送出  39 個位元組  GW INSTEK,GPD-3303S,SN:EK123456,V1.00\r\n
```

溫控器是位元組，所以印十六進位：

```
[dtb 127.0.0.1:53240] 收到   8 個位元組  01 03 10 00 00 02 C0 CB
```

結束：在視窗輸入 `q` 再按 Enter，或按 Ctrl+C。

參數：

| 參數 | 意思 |
|---|---|
| `--host 127.0.0.1` | 要聽哪個位址。預設只有這台電腦連得到。 |
| `--base-port 5561` | 第一台的埠號。四台依序是 gpd、dmm、bal、dtb。 |
| `--only gpd,dmm` | 只開其中幾台。埠號不會因此改變（dmm 還是 base-port＋1）。 |

出現「開不了埠」：多半是已經有一份在跑，或埠號被佔用。換一個 `--base-port`。

## 鍵盤：你就是站在儀器旁邊的人

在執行程式的視窗裡，打一個字母再按 Enter。

| 鍵 | 做什麼 |
|---|---|
| `p` | 天平：放上 50 g。先晃一下（US），大約 1.5 秒後穩定（ST）。 |
| `r` | 天平：拿走。 |
| `o` | 天平：放上 300 g，超過秤量，會送 OL。 |
| `k` | 天平：按面板上的 PRINT。穩定時送出一筆。 |
| `s` | 溫控器：拔掉感測器的線。再按一次接回去。 |
| `h` | 列出這張表。 |
| `q` | 結束程式。 |

## LabVIEW 怎麼連

### 資源名稱

VISA Resource Name 直接打字：

```
TCPIP0::127.0.0.1::5561::SOCKET
```

埠號換成要連的那一台。這種名稱通常不會自己出現在下拉選單裡，要自己打。

### 為什麼 SOCKET 要自己開 termination char

SOCKET 連線只是一條「位元組的水管」，沒有「一筆到這裡結束」的記號。
VISA Read 只有兩種方法知道該停了：

1. 讀滿你指定的位元組數。
2. 讀到結尾字元。

序列埠用 VISA Configure Serial Port 時，第 2 種已經替你打開。
SOCKET 沒有人替你開，所以 Read 會一直等，等到逾時。資料其實早就到了。

做法：對紫色的 VISA 線按右鍵，Create ▸ Property Node，選 Message Based Settings 底下的兩項。

| 屬性 | 寫入 |
|---|---|
| Termination Character Enable | True |
| Termination Character | 10（就是 `\n`） |

gpd、dmm、bal 的回覆最後一個字元都是 `\n`，所以都設 10。

**溫控器（dtb）相反：Termination Character Enable 要設 False。**
Modbus RTU 的資料是位元組，數值可能剛好等於 0AH，Read 會在中間就停。
改用「讀固定幾個位元組」。

### 送出的命令要自己帶結尾字元

VISA Write 送的就是你給它的字串，不會幫你補結尾字元。
字串常數按右鍵選 `'\' Codes Display`，才打得出 `\n`、`\r`。

沒帶結尾字元，儀器會一直等命令講完，不會回。你這邊就是逾時。
這一點可以在視窗的紀錄裡直接看到：收到的那一行後面有沒有 `\n`。

## 每台可以試的命令

### gpd：電源供應器（5561）

命令結尾 `\n`、`\r`、`\r\n` 都收。回覆結尾是 `\r\n`。不分大小寫。

| 送出 | 回覆 | 說明 |
|---|---|---|
| `*IDN?` | `GW INSTEK,GPD-3303S,SN:EK123456,V1.00` | 問它是誰 |
| `VSET1:12.5` | 沒有回覆 | 設定 CH1 電壓（0～32 V） |
| `VSET1?` | `12.500V` | 問設定值 |
| `ISET1:0.2` | 沒有回覆 | 設定 CH1 電流上限（0～3.2 A） |
| `OUT1`／`OUT0` | 沒有回覆 | 輸出開／關 |
| `VOUT1?`／`IOUT1?` | `5.001V`／`0.500A` | 實際輸出。輸出關著是 0。 |
| `STATUS?` | `11100001` | 8 個 0／1 |
| `ERR?` | `No Error.` 或錯誤訊息 | 問最後一個錯誤，問過就清掉 |

試試看：

1. 送 `*IDN?` 不帶結尾字元。等到逾時。看視窗的紀錄。
2. 送 `VSET1:5.0`（設定命令）然後去讀。也是逾時，但這次是正常的。
3. 送 `FOO`。沒有回覆。再送 `ERR?`，才看到 `Undefined header`。
4. 送 `ISET1:0.2`、`OUT1`，再問 `VOUT1?`。電壓掉到 2 V 左右：電流到上限了（CH1 接著 10 Ω）。

### dmm：數位電表（5562）

命令結尾要 `\n`。回覆結尾是 `\n`。長寫法、短寫法都收（`MEASure:VOLTage:DC?`＝`MEAS:VOLT:DC?`）。

| 送出 | 回覆 | 說明 |
|---|---|---|
| `*IDN?` | `Keysight Technologies,34461A,…` | 四欄，用逗號分開 |
| `MEAS:VOLT:DC?` | `+4.99873847E+00` | 量一次。大約等 0.35 秒。 |
| `CONF:VOLT:DC 10` | 沒有回覆 | 設定成量直流電壓 |
| `VOLT:DC:NPLC 100` | 沒有回覆 | 積分時間。可用 0.02、0.2、1、10、100。 |
| `READ?` | 一筆讀數 | 照目前設定量一次 |
| `INIT` 然後 `FETC?` | 一筆讀數 | 先量、後拿 |
| `*OPC?` | `1` | 做完了才回 |
| `SYST:ERR?` | `+0,"No error"` 或錯誤 | 一次拿一筆，最多存 20 筆 |
| `*RST`／`*CLS` | 沒有回覆 | 回到預設／清掉錯誤 |

試試看：

1. 故意打錯：`MEAS:VOLT:CD?`。沒有回覆，Read 逾時。
2. 送 `SYST:ERR?`，得到 `-113,"Undefined header"`。再問一次是 `+0,"No error"`。
3. 送 `VOLT:DC:NPLC 100`，再送 `READ?`。逾時設 2000 ms 會讀不到：量一次要 3 秒多。
   把逾時加長再試。也看看沒讀走的那一筆，下一次 Read 會先讀到它。

### bal：電子天平（5563）

命令結尾一定要 `\r\n`。只給 `\n` 或 `\r`，天平不理你。
回覆一筆固定 17 個位元組：15 個字元加 `\r\n`。

```
ST,+00050.00  g\r\n     穩定
US,+00036.88  g\r\n     還在晃
OL,+9999999E+19\r\n     超載
```

| 送出 | 回覆 | 說明 |
|---|---|---|
| （什麼都不送） | 沒有東西 | 預設是 Key mode：不問不送 |
| `Q` | 立刻一筆 | 可能是 US |
| `S` | 穩定時一筆 | 剛放上去要等 1.5 秒左右 |
| `SIR` | 每秒約 10 筆，一直送 | 開始連續輸出 |
| `C` | 沒有回覆 | 停止連續輸出 |
| `Z`（或 `R`） | 沒有回覆 | 歸零 |

試試看：

1. 連上去直接 Read。逾時。這不是壞掉，是 Key mode。
2. 按鍵盤 `p`，馬上送 `Q`，再送 `S`。比較兩筆的標頭，和各等了多久。
3. 送 `SIR`，然後 5 秒不要讀。按 `p`。再 Read 一次：讀到的是 5 秒前的舊資料（重量還是 0）。
   想要「現在」的重量：先清掉緩衝區再讀，或一直讀到沒有為止。
4. 按 `o`。看超載時那一筆長什麼樣子。程式要先看前兩個字元，再決定要不要轉成數字。

### dtb：溫度控制器（5564）

Modbus RTU。站號 1。最後兩個位元組是 CRC，低位元組在前。
一個封包請用一次 VISA Write 整個送出。

| 送出（十六進位） | 回覆 | 說明 |
|---|---|---|
| `01 03 10 00 00 02 C0 CB` | `01 03 04` PV PV SV SV CRC CRC | 讀 PV（1000H）和 SV（1001H） |
| `01 06 10 01 01 F4 DC DD` | `01 86 02 C3 A1` | 寫 SV＝50.0，被拒絕：還沒允許寫入 |
| `01 05 08 10 FF 00 8F 9F` | 原封不動回來 | 允許通訊寫入（0810H） |
| `01 06 10 01 01 F4 DC DD` | 原封不動回來 | 這次寫進去了 |
| `01 03 20 00 00 01 8F CA` | `01 83 02 C0 F1` | 位址不存在：例外回覆 |

- 數值是整數，單位 0.1 度。`00 FB`＝251＝25.1 度。
- 功能碼最高位元是 1（83H、86H）就是例外回覆，後面一個位元組是原因。
- 站號不對、CRC 不對：**完全不回**。和例外回覆是兩種不同的線索。
- 支援的功能碼：03（讀，一次最多 8 個字）、06（寫一個字）、05（寫位元）、02（讀位元）。

怎麼讀回覆（和課程 I7 的教法一樣）：先讀 3 個位元組，看第 2 個（功能碼）。
功能碼最高位元是 1：例外回覆，再讀 2 個就結束。
正常的 03 回覆：第 3 個位元組是資料的位元組數，再讀「那麼多個＋2 個 CRC」。
06 和 05 的正常回覆固定 8 個：再讀 5 個。

試試看：

1. 讀 PV。隔幾秒再讀：溫度會慢慢往 SV 升。
2. 把 CRC 兩個位元組對調再送。逾時。
3. 按鍵盤 `s` 拔掉感測器，再讀 PV：`80 03`。這不是 3277.1 度，是錯誤碼。

## 和真儀器的差別

| 這裡 | 真的 |
|---|---|
| 四台都走 TCP | GPD-3303S 是 USB 虛擬 COM；天平是 RS-232C；DTB 是 RS-485；34461A 是 USB 或網路線 |
| 沒有鮑率、同位 | 序列埠的都要設，設錯就是亂碼或收不到 |
| dmm 在 5562 | 34461A 走網路時，SCPI socket 的埠是 5025 |
| dtb 用「安靜 0.03 秒」判斷一個封包結束 | RTU 也是靠線上的安靜時間，長短跟鮑率有關 |
| 可以同時好幾條連線 | 序列埠一次只接一個對象 |
| 程式不關，設定就留著；重開程式等於儀器重新上電 | 一樣，但真儀器有些設定斷電也記得 |
| 電表只認得上面那幾個命令 | 真的有幾百個 |
| 半截命令 1 秒沒有下文就丟掉 | 說明書沒寫，每台不一定一樣 |

說明書沒寫清楚、這裡用模擬值的地方（實機請自己收一筆原始資料來看）：

- gpd：回覆帶不帶單位、回覆的結尾字元、沒有錯誤時 `ERR?` 的文字、`STATUS?` 最後兩位的意思。
- dmm：回覆的結尾字元、量一次要多久、讀數跳動的大小。
- bal：連續輸出每秒幾筆、秤量上限（這裡 220 g）、多久算穩定、下錯命令時的反應。
- dtb：寫入沒被允許時回哪一個例外碼、SV 的範圍（這裡 −20.0～500.0）、升溫的快慢。

這也是這一課要學的事：說明書不會什麼都寫。
先讓資料進得來，把原始回覆看清楚，再寫後面的程式。

## 測試

```
python -m pytest softinst/test_soft_instruments.py -q
```

測試會把四台開在隨機的埠，用 socket 真的連上去，一項一項對上面寫的行為。
大約跑 40 秒：有幾項要真的等儀器（電表慢速量測、天平穩定）。
